# daily-index

Ежедневная проверка открытых медиассылок и сборка одного M3U с русскоязычными телеканалами.

## Запуск в новом репозитории

1. В аккаунте `gwz-tools` создайте репозиторий `daily-index`, ветка `main`.
2. Для постоянной ссылки, которую плеер открывает без GitHub-авторизации, репозиторий должен быть Public. Название проекта не является защитой от ограничений GitHub.
3. Загрузите обычные файлы из ZIP в корень: `refresh.py`, `publish_dropbox.py`, `sources.json`, `order.txt`, `test_refresh.py`, `test_publish.py`, `README.md`. `setup_dropbox.ps1` — необязательный помощник для локальной разовой настройки. Файл `refresh.yml` создайте отдельно через Add file → Create new file: введите имя `.github/workflows/refresh.yml` и вставьте содержимое YAML из архива. Каталоги создадутся автоматически. Пошаговая инструкция — `START_HERE_RU.md`.
4. Добавьте три Dropbox-секрета по инструкции ниже. Затем Actions → Daily index → Run workflow → main → Run workflow. Это разовый проверочный запуск. Push, загрузки файлов и изменения кода не запускают сборку автоматически.
5. После успешной первой сборки появятся `playlistRU.m3u`, `strict_state.json`, `strict_status.json`.

Будущая ссылка плеера для этого имени репозитория:

`https://raw.githubusercontent.com/gwz-tools/daily-index/main/playlistRU.m3u`

До создания репозитория и успешной сборки эта ссылка не работает.

Workflow использует штатный `GITHUB_TOKEN` только для записи результата в собственный репозиторий. Личные токены, логины и ключи поставщиков потоков не нужны и не добавляются в M3U.

## Что выполняется ежедневно

Расписание: 03:17 UTC / 06:17 по Москве. GitHub может задерживать запуск; cron не гарантирует точное время. Один workflow, один job, один запуск в сутки. Обработка ограничена 35 минутами и 1 ГиБ скачивания; общий job — 45 минутами. Одновременно работают не более четырёх проверок. Одинаковый URL проверяется один раз за сборку; краткий повтор допускается только при временном сетевом сбое. При исчерпании лимита неполный результат не публикуется. Подробнее: [расписание GitHub Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

- Скачиваются 154 исходных плейлиста ТВОЕ ТВ, loganet и dmi3y-tv из ранее сохранённого каталога. Включены региональные и мобильные версии.
- На трёх заданных страницах дополнительно ищутся прямые M3U/M3U8-ссылки. JavaScript не исполняется, произвольный обход сайтов не выполняется.
- Справочник iptv-org `languages/rus.m3u` используется только для сопоставления языка и названий, а не как дополнительный источник потоков. Если справочник недоступен, остаются явные языковые метки и встроенные проверяемые вручную соответствия `russian_aliases`.
- Записи отбираются по явной русской языковой метке либо точному имени/идентификатору из справочника. Кириллица сама по себе не считается доказательством языка. Явная иностранная метка исключает запись. Языковые теги аудиодорожек дополнительно проверяются, когда присутствуют.
- Для канала сначала проверяется ранее выбранный адрес. При сбое проверяются альтернативы из свежей сборки, пока не найдётся рабочая. Остальные резервные адреса не объявляются проверенными. HTTPS имеет приоритет среди новых вариантов.
- В плейлисте остаётся одна проверенная ссылка на канал. Отличающиеся часовые сдвиги сохраняются отдельно; HD/SD-суффиксы при сопоставлении удаляются. Неизвестные и несовпадающие варианты названий можно добавить в `russian_aliases`.
- Если канал не работает ни по одному адресу, он исключается из новой сборки. На следующем запуске он снова может появиться из источников.
- Ранее выбранные ссылки повторно проверяются, даже если исходная страница временно недоступна. Старые положительные результаты не подменяют новую проверку.
- Если не прошло ни одного канала или выполнение оборвалось, новый плейлист не публикуется. Прежний файл сохраняет прежнюю дату проверки; задание становится красным, отчёт доступен в артефакте `run-report`. Это резервная предыдущая сборка, а не подтверждение сегодняшней работоспособности.

## Строгая фильтрация ссылок

Для URL **потоков**, всех HTTP-перенаправлений, HLS-вариантов, адресов сегментов и initialization-сегментов применяется одна политика:

- только HTTP/HTTPS с публичными доменами или публичными IP;
- запрещены все query-параметры (`?...`), включая внешне безобидные; это намеренно строгая политика;
- запрещены логин/пароль в адресе, fragments, дополнения `|User-Agent=...`, известные шаблоны подписок, именованные токены и подозрительные длинные идентификаторы в пути;
- запрещены записи, требующие специальных заголовков, Referer, cookies, Kodi/VLC-параметров или лицензии;
- запрещены HLS с ключом шифрования, включая AES-128 и SESSION-KEY. Ключи не извлекаются, не удаляются из URL и не обходятся;
- вложенные URL проверяются до обращения к ним; подозрительные URL целиком отбрасываются, а не «очищаются» от параметров;
- редиректы обрабатываются вручную; cookies между запросами не сохраняются;
- DRM, DASH, нестандартные протоколы, отдельные HLS-аудиорендиции, HLS byterange и LL-HLS сейчас исключаются. Это уменьшает покрытие, зато такие потоки не объявляются прошедшими проверку.

Правила query/path-фильтра действуют на медиапотоки. Адреса страниц и скачиваемых исходных списков могут иметь обычные параметры скачивания; они не попадают в итоговый M3U.

Без знания серверной реализации невозможно распознать абсолютно любой короткий скрытый ключ внутри пути URL. Фильтр отклоняет известные и подозрительные формы; отсутствие токена не доказывает принадлежность потока телеканалу или наличие разрешения на ретрансляцию. Проект не обходит платный доступ и не хранит/раздаёт видео.

## Проверка воспроизведения

HTTP 200 недостаточно. Для HLS скачиваются несколько актуальных сегментов, проверяются вложенные ссылки и отсутствие шифрования. Для непрерывного HTTP MPEG-TS читается ограниченный образец. FFprobe должен обнаружить видео и аудио; FFmpeg должен действительно декодировать образец и выдать не менее десяти видеокадров. Декодер получает только локально скачанные данные и не выполняет сетевых запросов. Документация: [FFmpeg](https://ffmpeg.org/ffmpeg.html).

Проверка подтверждает декодирование короткого образца в момент запуска на сервере GitHub. Она не гарантирует круглосуточной стабильности или доступности из домашней сети, не распознаёт речь и не отличает все возможные телевизионные заглушки от передачи. Если источник неверно подписан или имеет региональные ограничения, результат требует уточнения. Сомнительные языковые записи исключаются, а не определяются по алфавиту названия.

## Файлы результатов

| Файл | Содержимое |
|---|---|
| `playlistRU.m3u` | Итоговые проверенные каналы |
| `strict_status.json` | Время проверки, SHA-256 плейлиста, число каналов, отказы источников, причины исключений, заменённые и пропавшие каналы |
| `strict_state.json` | Последние выбранные адреса для повторной проверки на следующем запуске |

Исходные отклонённые URL с ключами не включаются в отчёт. При публикации workflow проверяет SHA-256 и отказывается записывать результат поверх новых изменений исходников. Рабочие видеофрагменты создаются во временной папке и удаляются после теста.

## Локальный запуск

Нужны Python 3.12, `ffmpeg` и `ffprobe`. Дополнительные Python-пакеты не требуются.

```bash
python -m unittest discover -p 'test_*.py' -v
python refresh.py --collect-only
python refresh.py
```

`--collect-only` проверяет сбор и фильтры, записывает диагностический отчёт и **не создаёт непроверенный плейлист**.

## Проверка подготовленной версии

Выполнены 26 тестов: URL-фильтры, перенаправления на токены, непубличные адреса, шифрование, токены в сегментах, разбор M3U, язык, дубли, замена отказавшего адреса, сохранение предыдущего файла при полном сбое, сортировка, лимит трафика, отказ от устаревшей сборки, идентичность файла Dropbox и контрольная сумма. В тестах FFmpeg декодировал настоящее сгенерированное видео со звуком.

Полная проверка внешних потоков и запуск GitHub Actions ещё не выполнены: в среде подготовки недоступно DNS-разрешение внешних источников. Никакое количество живых каналов в этой версии заранее не заявляется. Нужна первая успешная сборка в новом репозитории.


## Сортировка

`order.txt` содержит прежний каталог для порядка и категорий, а не разрешение включить любой перечисленный канал. Языковой фильтр применяется независимо: зарубежные каналы из прежнего списка не добавляются автоматически.

Порядок разделов: Федеральные → Новости → Кино → Кинозалы → 4K / UHD → Детские → Спорт → Познавательные → Развлекательные → Музыка → Разное → 18+. Внутри разделов сначала идёт сохранённый порядок `order.txt`, остальные каналы сортируются по названию с естественным порядком чисел. Качество HD/SD объединяется при сопоставлении, поэтому HD-версия канала не обязана попадать в отдельную группу качества. Неопознанные группы сводятся к «Разное».

## Автоматическая публикация в Dropbox

Назначение уже задано: `/IPTV-GWZ/playlist-full.txt`, существующий ID проверяется перед записью. Каждый успешный цикл сначала публикует проверенный M3U в GitHub, затем обновляет этот же Dropbox-файл с проверкой его ревизии. Новые дубли файла и новые общие ссылки не создаются. После загрузки сверяются размер, Dropbox content hash и ID; файл повторно проверяется через API.

В Settings → Secrets and variables → Actions → New repository secret нужны:

| Name | Значение |
|---|---|
| `DROPBOX_APP_KEY` | App key приложения Dropbox |
| `DROPBOX_APP_SECRET` | App secret приложения Dropbox |
| `DROPBOX_REFRESH_TOKEN` | Refresh token с разрешением offline |

Если значения сохранились от предыдущего проекта, добавьте их в новый репозиторий. Секреты из одного репозитория не переносятся в другой автоматически. GitHub не показывает ранее сохранённые значения. Если refresh token утрачен, получите новый через помощник `setup_dropbox.ps1` по инструкции `START_HERE_RU.md`.

Нужны доступ Full Dropbox для существующей папки и права `files.metadata.read`, `files.content.write`. Это служебная авторизация загрузчика Dropbox, она не попадает в ссылки телеканалов. Если секретов нет, синхронизация завершается ошибкой, а не выдаёт успешный пропуск. Если Dropbox недоступен, GitHub-версия может обновиться, а Dropbox сохранит старую; job будет красным. Следующий ночной запуск повторит полный цикл.

Документация: [GitHub Secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets), [Dropbox OAuth](https://developers.dropbox.com/oauth-guide), [Dropbox content hash](https://www.dropbox.com/developers/reference/content-hash).

Проект можно хранить в приватном репозитории, если плеер использует Dropbox. Для приватного репозитория нужно учитывать доступную квоту GitHub Actions. Никакая конфигурация или нейтральное имя не снимает ограничение, наложенное GitHub на аккаунт: для запуска нужен аккаунт, в котором Actions разрешены.
