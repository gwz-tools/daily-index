# Установка daily-index — без доступа помощника к GitHub

Пакет содержит готовые исходники. Реальные потоки нужно проверить первым запуском GitHub Actions: в среде подготовки внешние адреса не разрешались через DNS. Локальные тесты прошли. Установка не восстанавливает заблокированные GitHub Actions: для запуска нужен разрешённый доступ к этому сервису.

## 1. Создайте новый репозиторий

В аккаунте `gwz-tools` нажмите New. Имя: `daily-index`. Description: `Daily validation of public media links`. Ветка: `main`.

Можно выбрать Private, если основной плейлист будет открываться из Dropbox. Public нужен для дополнительной общедоступной raw-ссылки GitHub. Название не гарантирует отсутствие ограничений со стороны GitHub.

## 2. Загрузите обычные файлы

Распакуйте ZIP. Add file → Upload files. Следующие **семь файлов** загрузите в корень нового репозитория:

1. `refresh.py`
2. `publish_dropbox.py`
3. `sources.json`
4. `order.txt`
5. `test_refresh.py`
6. `test_publish.py`
7. `README.md`

Их можно выбрать одновременно. Сохраните через Commit changes в `main`.

`START_HERE_RU.md` — эта инструкция, загружать необязательно. `setup_dropbox.ps1` — локальный помощник, загружать тоже необязательно. ZIP целиком загружать не нужно.

## 3. Добавьте YAML в правильное место

В репозитории: Add file → Create new file.

В поле имени файла целиком введите:

```text
.github/workflows/refresh.yml
```

Откройте `refresh.yml` из распакованного ZIP Блокнотом, скопируйте всё содержимое и вставьте в редактор GitHub. Commit changes в `main`.

GitHub создаст обе папки из указанного пути. Создавать их по очереди не требуется. YAML в корне репозитория не запустится. Каталог `.github/workflows` обязателен.

## 4. Подключите Dropbox один раз

В репозитории: Settings → Secrets and variables → Actions → New repository secret.

Создайте три секрета с точными именами:

```text
DROPBOX_APP_KEY
DROPBOX_APP_SECRET
DROPBOX_REFRESH_TOKEN
```

Значения нужны от вашего Dropbox-приложения. В код, YAML и сообщения чата их вставлять не нужно. Секреты прежнего GitHub-репозитория автоматически сюда не переносятся.

Если значения сохранились, используйте их. Если нет:

1. Откройте [Dropbox App Console](https://www.dropbox.com/developers/apps), выберите своё прежнее приложение. App key и App secret находятся в его настройках. Для существующего `/IPTV-GWZ/playlist-full.txt` нужен доступ Full Dropbox, не App Folder.
2. На вкладке Permissions проверьте `files.metadata.read` и `files.content.write`, сохраните изменения.
3. Откройте `setup_dropbox.ps1` Блокнотом, скопируйте содержимое и вставьте в PowerShell. Скрипт выполняется только на вашем Windows-компьютере.
4. Введите App key и App secret. Откроется обычное окно авторизации Dropbox. Авторизуйте приложение и вставьте выданный одноразовый код в PowerShell. Секрет и код при вводе скрываются.
5. Помощник последовательно поместит значение каждого из трёх секретов в буфер обмена. Создавайте соответствующий GitHub secret, вставляйте значение и сохраняйте. Нажимайте Enter в PowerShell только после сохранения очередного секрета.
6. В конце помощник очищает буфер обмена. Значения не записываются в файлы и не печатаются в терминал. После настройки закройте окно PowerShell.

Файл назначения уже настроен: `/IPTV-GWZ/playlist-full.txt`. Обновляется именно существующий файл; его общая ссылка сохраняется. Если Dropbox-приложение привязано к другому аккаунту или файл переместили, загрузчик откажется писать в другое место.

## 5. Сделайте один пробный запуск

Actions → Daily index → Run workflow → main → Run workflow.

Зелёный результат должен включать успешные шаги **Refresh**, **Validate result**, **Publish verified output**, **Update existing Dropbox playlist**.

Если запуск красный, откройте ошибочный шаг и пришлите его текст или скриншот без секретов. Отчёт `run-report` находится внизу страницы запуска, в Artifacts. Он покажет количество каналов, отказы источников и причины исключения.

До первой успешной сборки новый `playlistRU.m3u` отсутствует. Старый Dropbox-файл остаётся прежним.

## После настройки

Один workflow, один job, запуск ежедневно в 06:17 по Москве (03:17 UTC). GitHub может задерживать старт. Загрузки файлов, коммиты и изменения исходников не запускают проверки автоматически.

Ежедневно выполняется: 154 исходных плейлиста + поиск M3U на трёх страницах → русскоязычные каналы → фильтр токенов/ключей → короткая проверка видео и звука → сортировка → GitHub → Dropbox.

Нагрузка ограничена: четыре параллельные проверки, 35 минут обработки, 1 ГиБ скачивания, общий job максимум 45 минут. Обычно работа может завершиться раньше; реальное время и количество каналов станут известны после первого запуска. При исчерпании лимита неполная сборка не публикуется.

Ссылки на каналы с токенами/ключами исключаются целиком; ключи не обходятся и не вырезаются из адресов. Отсутствие токена не гарантирует отсутствие любой видеозаглушки. Проверка подтверждает декодирование образца, а не распознавание содержания передачи.
